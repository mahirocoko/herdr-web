# Project Overview — historical

> Superseded at source promotion on 2026-10-19. The following describes retired fork owners, not the current source-native application. Use the root README/AGENTS and `docs/upstream-parity.md`.

Active Web-held intents appear as a compact card stack directly above the composer: front item with manual actions, decorative backs/count and an expandable bounded list. The stack uses the existing Root-held state and original-record callbacks; it is not a native queue, automatic scheduler or new store. Empty, restored and completed records do not create a live stack; read-only historical evidence remains in Chat. Blocked-agent views retain the stack but strict target/mode fencing withholds Send authority.

Ordinary Send evidence is distinct from Web-held Queue. Current sending/uncertain/rejected issues remain visible in Chat; acknowledged, restored, stale and corroborated receipts are available in the closed `Submission history (not queued)` disclosure, with the global Clear control and its no-cancellation explanation. This is presentation only: no stored evidence is automatically cleared, retried or upgraded into delivery authority.

## Product Job

Herdr Web lets the operator inspect and steer existing Herdr panes from a phone or tablet over a private Tailnet. It is an agent-aware mobile companion, not a generic SSH client.

## Architecture

```text
Mobile browser
  -> Tailscale Serve HTTPS/WSS
  -> Bun server on 127.0.0.1:8787
  -> Unix Domain Socket (~/.config/herdr/herdr.sock, protocol 22)
  -> herdr terminal session observe (Stream mode observer CLI subprocess) or herdr terminal session control (opt-in shell-only control CLI subprocess)
```

The browser app is React + Vite + xterm with React Router Framework Mode (v8.4.0, `ssr: false`) powering file-based client routing (`/` for root resolver, `/spaces/:workspaceId` for Space command center, and `/settings` for Chat appearance and push management). Interactive controls consume exact Base UI 1.8.0 primitives (`@base-ui/react@1.8.0`) including Button, Input, Textarea, Checkbox, Switch, RadioGroup, Select, Sheet, Tabs, Toggle, and ToggleGroup, backed by canonical CSS recipes in `src/components/ui/recipes.css` (imported by `src/app.css`), with an owned semantic Textarea primitive. The October 9 shell + Chat candidate studies BoardUI Dashboard / AI Chat dark neutral material using project-owned assets; human visual acceptance is pending. Earlier `devswha/herdr-web-ui` (MIT copyright 2026 devswha) adaptation remains credited for anatomy, not current palette authority. Current owners and provenance are in `docs/styling.md`.

The server is direct `Bun.serve`. Background Web Push alerts use standard Web Push (`web-push`) and Space-aware labels (`Space: <label>`). Needs input follows immediate enabled-Tab attention transitions. Done emits once per observed work round when all canonical agents in the Space are done/idle, including muted Tabs, excluding empty shells, and waiting on working/blocked/unknown agents. At least one enabled Tab is required; the first canonical Tab is enabled by default, with live overrides via `push-tab-policy.json` and `/api/push/tab-policy`. The click target is a validated Space deep link (`/spaces/<encoded-id>`), focusing an existing client only upon positive app acknowledgment (stale/pre-update bundles must close/reopen before clicks can focus them), while physical iOS switching of an already-open PWA remains unverified under investigation. Subscriptions use an atomic private JSON store. There is no relational database, user account system, or arbitrary PTY takeover. Opt-in Terminal Control Mode exists solely as an authenticated same-origin WebSocket session bound to an exact verified idle shell pane under strict lease control, with no agent pane control and no `--takeover` flag. Remote Tailnet Terminal Control requires configured owner identity from Push config (`ownerLogin`); without it remote requests fail closed, while narrow loopback development exception remains. It does not require Push enrollment/subscription, only owner config.
