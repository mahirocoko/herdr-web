# Herdr Web Agent Guide

## Current Reality

- Active document-owned Web-held intent presentation belongs to `HeldQueueStack` in the App footer directly before the existing composer, including blocked-agent visibility with strict Send fencing. Front card, decorative noninteractive backs, count and expanded bounded list share Root's existing record callbacks; display ordering is first-observed presentation only, never a delivery scheduler. Restored and terminal held evidence remains read-only in Chat; do not duplicate live actionable cards there or mix ordinary Send receipts into the stack. An empty stack reserves no space. Shell enqueue eligibility, original targets, capability lifetime and server delivery contracts are unchanged.

- Ordinary Send receipts are not a queue. `SubmissionReceipts` in Chat keeps current matching sending/uncertain/rejected issues visible; acknowledged, restored, stale and corroborated records live in one initially closed `Submission history (not queued)` disclosure. Global Clear and its no-cancellation explanation belong inside that read-only evidence disclosure. Preserve stored provenance and strict corroboration; hiding historical presentation must never confer delivery authority or automatically retry/clear records. Capability-owned held intents remain a separate owner.

- Chat's current owners are `server/conversation/` for selected native records, `server/prompt-parser.ts` for the pinned source parser, `server/interactive-prompt.ts` plus the existing authenticated action/coordinator pipeline for typed answers, and `use-interactive-prompt` for binding-specific browser readiness. Implemented macOS readers cover Letta/Agy/Codex/Claude/OMP/OmO/GJC/PI; never equate fixture coverage with every provider's live availability. Unknown/unread Chat prompt state must not fall through to generic Composer input. Native read/send is not conditional CAS; preserve the documented identical-question-repeat limitation. Question remains read-only; do not create another prompt/answer owner.

- Private, single-user mobile command center for a local Herdr server.
- Bun owns package management and the server runtime. React, React Router Framework Mode (v8.4.0, `ssr: false`), Vite, xterm, and exact Base UI 1.8.0 primitives (`@base-ui/react@1.8.0`) own the browser app. `src/app.css` owns dark semantic tokens and shell geometry; `src/components/ui/recipes.css` owns shared control states. The October 9 shell + Chat candidate studies BoardUI Dashboard / AI Chat neutral material and anatomy, with project-owned assets/fonts and no light variant. Earlier `devswha/herdr-web-ui` (MIT copyright 2026 devswha) attribution remains for adapted anatomy, not current palette authority. Human visual acceptance is pending; do not extend the candidate to new product surfaces automatically.
- Socket-first backend integration using the installed Herdr 0.9.4 host's public NDJSON Unix socket API (tracked protocol 22, schema_version 1) for health, snapshots, pane validation, actions, and reads.
- Backend event-driven snapshot bridge (`server/snapshot-bridge.ts`) preflights a snapshot for pane IDs, opens one shared `events.subscribe` connection with global lifecycle plus exact per-pane `pane.agent_status_changed` subscriptions, waits for acknowledgement, then fetches an authoritative snapshot. Topology changes rebuild the subscription before resnapshotting.
- Preserve Herdr's status semantics exactly: pane `agent_status` is the effective pane state, while Tab and Space `agent_status` are upstream attention aggregates (`blocked > unseen idle/done > working > seen idle > unknown`), not “any agent currently working” summaries. Raw snapshot DTOs, wire schema, socket protocol, and action targets preserve native attention semantics without alteration. Push Needs input uses native Tab attention; Push Done derives all-agent Space completion separately without rewriting snapshot statuses. For browser UI presentation, Herdr Web computes a pure derived Activity view (`blocked > working > done > idle > unknown`) from leaf panes (`src/utils/activity-status.ts`) across navigation consumers (Space dot, Tab compact indicator, Pane plain word + dot), displaying current activity truthfully while preserving native attention in tooltips and accessible labels (`Activity: ... (Native attention: ...)`).
- Keep browser-facing pane-read sources stable at the HTTP boundary. In particular, map `recent-unwrapped` to the raw Socket API enum `recent_unwrapped` inside `server/herdr-adapter.ts`; do not leak the wire spelling into browser hooks or UI state.
- Browser snapshot read recovery belongs to `use-snapshot` and `src/services/snapshot-reader.ts`: polling stops only when the backend bridge reports `connected` and a current authoritative snapshot read has succeeded; WebSocket open alone is not healthy. Hidden/pagehide/offline retires the read socket and aborts HTTP once; the first visible/pageshow/online resumes immediately, while overlapping or delayed notifications preserve the new attempt. Current successful HTTP/pushed read truth owns UI readiness independently of bridge status; unhealthy bridge status keeps fallback polling active but cannot demote that successful read, and healthy status cannot strand a failed read without polling. Event application pings every 15s receive current bridge status (no native operation), with a 10s connect/response deadline, so idle topology is not mistaken for disconnection. HTTP snapshot reads are single-flight, no-store, bounded to 10s through body parsing, and fenced against newer pushed snapshots, recovery generations and cleanup. HTTP fallback remains active in all unhealthy bridge states and CLI mode; recovery never sends/replays mutations or reacquires Terminal Control.
- Panel and Question surfaces retain truthful HTTP polling for text content refresh (`/api/pane/read`), as lifecycle events reflect session/pane structure rather than terminal buffer text changes.
- Explicit `HERDR_TRANSPORT=cli` fallback mode remains available for operational compatibility and debugging.
- Chat is the default reading surface for newly selected agent panes; shell panes default to Terminal (internal `stream` mode). Wait for matching pane metadata before consuming a selection transition. Status updates preserve a manually selected view; unavailable Chat records show a reason and explicit Go to Terminal action rather than silent fallback.
- Stream mode fits the actual native PTY grid to the browser canvas via `herdr terminal session control <TARGET> --cols <N> --rows <N>` with debounced, deduped resize and bounded native source scroll commands (`terminal.scroll` with signed `deltaRows`, `to: 'latest'`, or `reset: true`) on the same WebSocket, valid for 1..500 cols and 1..200 rows without a min-40 restriction (allowing mobile 35-col viewports to fit natively). Wheel and touch drag in Live mode adjust native reading offset via `pane.scroll`, while Latest resets offset to 0 and incoming updates do not force the reader back while scrolled up (`offset > 0`). Terminal fit automatically releases on document hidden/pagehide/unmount/Chat/pane switch (restoring native desktop geometry automatically without manual resize); a compact Pause fit / Resume Live button in the scope bar allows manually returning to desktop PTY dimensions. Exactly one fitted reader is permitted per terminal; non-WebSocket joins retain HTTP 409, while browser denial-only sockets close with code 4409 and `FIT_BUSY`/`FIT_BLOCKED_BY_CONTROL` (manual Retry) or `FIT_RELEASING` (bounded retirement retry), without reserving another session or spawning a producer. Resize and scroll authority do not acquire operation-coordinator input claims, so Composer Send and agent prompts coexist concurrently without contention. Shell input control exclusively blocks fit admission and retires the fit producer before lease activation. Local 2D panning remains active when scrolled away. Source history is bounded by the native scroll API; distinguish native source viewport scrolling from agent-app/internal scroll when no history exists (alternate-screen applications may expose zero source scrollback). Question is offered for blocked panes without automatically hijacking the current view. Composer Send remains default; direct agent live typing is not implemented or authorized by this surface change.
- Focused server-side browser projection at HTTP `/api/snapshot` and WebSocket `/api/events` boundaries minimizes snapshot payloads, constructing fresh allowlisted objects and stripping unknown fields, `layouts`, `state_labels`, raw arbitrary token maps, worktree paths/path-like labels, and Letta tokens. Preserve only fields required by browser selection/navigation/action identity/terminal source behavior, including strict workspace/pane token allowlists and snapshot-agent target/pane ID plus nested session value/ID for replacement-safe fallback mutations.

## Non-Negotiable Boundaries

- Never bind the app server to `0.0.0.0` or expose it directly to the LAN or public internet.
- Never add an arbitrary raw shell service. Mutations and terminal inputs map strictly to typed raw methods (`pane.send_input` with text and Enter atomically, `agent.prompt`, `pane.send_keys`, `tab.create`, `workspace.create`, `workspace.close`, `tab.close`, `agent.start` with server-owned Letta `['--new']`, `worktree.list/create/open` with exact verified source and native-default checkout ownership) or bounded CLI argv arrays in CLI mode, never shell strings.
- Mutations and WebSocket upgrades (`/api/events`, `/api/terminal`, `/api/terminal/control`) require an exact same-origin check. Keep CORS closed.
- Mutations (`/api/action`), terminal control (`/api/terminal/control`), and push management share one mutation owner auth validator using configured `ownerLogin` from push config (with narrow loopback development exception), failing closed on Tailnet if missing or mismatched. Push subscription is not required for action or control.
- Every prompt/terminal-input/keys action requires `operationId` and exact target identity `{paneId, terminalId, expectedMode, agentSessionId?}`. `agentSessionId` is required when authoritative agent evidence exposes one and must be omitted for shell panes. Authoritative snapshot preflight rejects missing targets, terminal replacement, expected-mode mismatch, and agent-session replacement (using canonical `isAgentPane` where literal `'shell'` is not agent evidence). Concurrency is coordinated per-terminal-target process-locally via a token-fenced admission arbiter reserving the operation ID and pane claim synchronously before any await; actions on leased control panes are rejected with 409 contention. Pre-dispatch snapshot fetch failure abandons the attempt uncached (502 rejected), while authoritative preflight rejection caches 409/404. Duplicate operation IDs replay cached terminal results within TTL (refreshing genuine LRU position); conflicting payload reuse is rejected.
- New shell tab creation (`type: tab-create`) requires socket transport (CLI returns 409), hardcodes `focus: false`, derives CWD from fresh source pane `foreground_cwd || cwd`, verifies workspace membership, correlates the exact RPC response type (`tab_created`) and ID, and verifies returned tab/root pane IDs against post-creation snapshot without inferring causation from snapshot deltas or CWD. Ambiguous timeout, malformed response, or daemon error without correlated identity returns truthful `outcome: 'unknown'` without retry; no snapshot inference is performed. In the UI, New Shell Tab unknown state is strictly gated and clears only on an explicit successful snapshot refresh (`result === true`). By contrast, prompt/terminal-input unknown state has no automatic retry; drafts and warnings are retained, where inspection before manual resubmission with a fresh operation ID is guidance, not an enforced gate.
- Space/Tab lifecycle actions remain variants of `POST /api/action`, not new routes. `workspace-create` accepts only an optional bounded label plus an optional exact terminal-backed source; it hardcodes `focus: false`, requires the full correlated `workspace_created` response, and proves the exact returned Space/Tab/root pane in a post-snapshot. `workspace-close` always sends `close_group: false`; `tab-close` rejects the last canonical Tab. Both close actions require a client-frozen raw membership manifest, compare it against a fresh immediately-before-RPC snapshot, require the exact `{ type: 'ok' }` response, and prove target/descendant absence afterward. Membership drift is a zero-RPC 409 rejection. Timeout, malformed response, or failed postcondition is `outcome: 'unknown'` and is never retried automatically.
- The operation coordinator owns one process-local topology readers/writer gate in addition to pane claims: Space/Tab create/close actions are exclusive; prompt/input/keys and the full Terminal Control lease lifecycle hold shared topology claims; Tab notification-policy writes hold a transient shared topology claim. Replay/conflict is resolved before contention, and every release is token-fenced.
- Browser lifecycle tickets are Root-owned and survive Drawer dismissal and route changes. Pending, unknown, and reconciliation-failed tickets block another lifecycle mutation. Unknown clears only after explicit successful snapshot inspection and is never retroactively called success; an observed create navigates only when a refreshed snapshot confirms exact returned IDs and current route/selection still match the captured origin.
- Keep navigation ownership visually separate: the hamburger opens the Herdr-style Spaces side sheet with Space selection and Space lifecycle; the header Tab trigger opens the active-Space Tabs & Panes bottom sheet with pane selection and Tab lifecycle. Under the zoned header, the active-Space horizontal native Tab rail provides single-line tab navigation across current Space tabs (sorted by number with truthful status dot, selecting real existing panes in the chosen tab). Header search button opens NavigationSearch (snapshot-only search across Spaces, Tabs, and Panes without filling or dispatching commands). PromptComposer commands opens the command picker (`InteractionPickerSheet`). Do not restore Space pills/actions inside the Tab hierarchy. For Space source metadata, display only the allowlisted Sidebar-published tokens (`mahiro_workspace_branch`, `mahiro_workspace_git_status`, `mahiro_workspace_worktree`) and never infer Git state client-side.
- Repo-configured interaction catalog (`GET /api/interactions/catalog`) canonicalizes startDir via `realpathSync` and resolves the nearest ancestor `.herdr/commands.json` only within the target pane's Git repository, strictly as inert draft fill strings. Missing config returns an empty catalog; invalid config fails with 422. Native catalog is not established, command selection remains local/client-side, and historical agent launch presets remain disabled and unreferenced. T171 launch ACK correlates exact required pane/terminal and server-owned argv; nullable/omitted native kind/name/session do not invalidate ACK, while provided nonnull kind/name must match. ACK without returned session remains not ready; later observation cannot upgrade an original UNKNOWN receipt. The approved T171 checkpoint exposes only typed `agent-start` through authenticated `POST /api/action` and `executeAgentStart`: human-supplied safe name, Letta kind (installed native help supports it), exact pane/terminal, server-owned `args: ['--new']` for a new Letta conversation; configured model/permissions unchanged. No client args/model/effort/permission overrides, shell fallback or automatic retry exists. Native worktree candidate controls now belong to the existing Spaces sheet and typed `/api/action` family: exact source Space/pane/terminal, path-free bounded native listing, stateless repository/checkout hashes, relist before open/create, and native-default branch/base/path ownership. Browser paths/cwd/trust/argv overrides are refused; `trust_repository: false` and `focus: false` are fixed. Open associates an existing checkout, Create explicitly makes files/Space for a safe simple branch name; neither starts an agent. Native daemon owns Git canonicalization/symlink/trust policy, not Web filesystem code. Unknown mutations never retry automatically; exact correlated response and post-snapshot target/cwd proof are required for observed. Worktree mutations hold exclusive topology plus pane claims and reuse Root tickets/reconciliation; list uses shared admission. Source/branch facts are never inferred from client paths. Native/browser worktree proof remains unestablished. PaneDrawer offers explicit Start Letta only for idle shell candidates with exact terminal and no agent/session evidence; server process verification remains authoritative. Its confirmation freezes pane/terminal and human name, then dispatches through Root's existing lifecycle ticket. Pending, acknowledged and unknown tickets survive Drawer/route changes and fence new intent; acknowledged is never treated as observed/auto-cleared. Explicit successful Refresh and inspect releases the gate without replaying launch. Exclusive topology plus pane admission fences control/actions; fit admission is blocked and producer retirement confirmed before fresh idle-shell verification. Exact `agent_started` correlation is ACK, not readiness: a subsequent matching terminal/session and native idle/done status are required for `ready: true`. Missing evidence stays acknowledged-not-ready; ambiguous dispatch stays unknown. PaneDrawer, SpaceDrawer and Tab action-menu receipt presentation preserve ACK-not-current-readiness semantics; fresh browser QA and authorized native proof remain separate gates.
- Custom actions and terminal key rail customization are managed through a single typed validated browser-safe storage owner (`localStorage` key `herdr_custom_actions_v1`). Storage enforces a 32 KiB byte limit (`MAX_STORAGE_BYTES`), bounded action/character counts, malformed JSON recovery, and clear scope partitioning (Global vs Space). Explicitly label Space scope, not repo/project, as Space is the canonical stable workspace unit in Herdr Web. Writing `.herdr/commands.json` or creating server-side config editors is strictly forbidden. Repo-configured catalog items remain strictly read-only and merge with user custom actions by explicit provenance (`'repo-config'` vs `'user'`) with no overwrite. Direct execution is out of scope: draft-fill fills composer inertly and requires explicit Send; terminal-key actions execute via the existing target-fenced `/api/action` mutation pipeline (`POST /api/action` with `type: 'keys'`). Canonical terminal keys (`CANONICAL_TERMINAL_KEYS`) extend safe key presets (`Shift+Tab`, `Ctrl+D/L/Z/R/A/E/W/U`, `Space`, `Backspace`, `Esc`, `Tab`, `Enter`, `Ctrl+C`, arrows) and map to ANSI control sequences in Terminal Control Mode. Crucially, upstream Herdr 0.9.3 parser evidence (`src/config/keybinds.rs` and `src/app/api_helpers.rs`) does not recognize `delete` or `del`; `delete` is strictly excluded from `ALLOWED_KEYS` and rejected with 400. The terminal key rail scrolls horizontally within its container without document overflow. Add/manage entry switches views within the single `InteractionPickerSheet` without stacking modal sheets.
- Stream observer remains available for every pane and is default for shell panes; agent panes default to Chat. Opt-in shell-only Terminal Control Mode (`/api/terminal/control`) is available solely for verified idle shell panes via authenticated same-origin WebSocket under strict single-lease management; control footer restores only after server status (`GET /api/terminal/control/status`) confirms the exact pane is unleased, while quarantine stays releasing. Remote Tailnet Terminal Control requires configured owner identity from Push config (`ownerLogin`); without it remote requests fail closed, while narrow loopback development exception remains. It does not require Push enrollment/subscription, only owner config. Never activate or offer control for agent panes. Never use `--takeover` or expose an arbitrary shell endpoint.
- Do not claim Tailscale identity, latency, or authentication unless the runtime proves it.
- Web Push notifications use fixed event copy plus bounded Space label (`Space: <label>`) for `Needs input` and `Done`. Needs input retains immediate native Tab non-blocked → blocked transitions under per-Tab policy (first canonical Tab enabled by default, live overrides supported). Done emits once per observed working round only when every canonical agent pane in the Space is done/idle, including muted Tabs; empty shells are excluded by server `isAgentPane`, and working/blocked/unknown agents prevent completion. At least one enabled Tab is required to deliver Done. Initial completed/idle states, policy-only changes, and removal of busy agents never manufacture completion; topology/terminal/session changes establish a silent baseline. Notification payloads, metadata, tags, and navigation never include pane/tab IDs, terminal output, prompts, question text, cwd, agent output, or secrets. State delivery is best-effort snapshot observation (transitions missed between snapshots/disconnection cannot be delivered; process restart baselines current state; provider TTL is 60s). Notification click targets the Space route (`/spaces/<encoded-id>`), never a Tab or pane; for an already-open same-origin client, the Service Worker focuses it only upon positive app acknowledgment (`herdr:workspace-opened`), with unknown spaces, invalid data, or timeouts causing zero navigate, zero focus, and zero window opens (stale/pre-update PWA bundles must close and reopen before clicks can focus them); physical iOS switching of an already-open PWA remains an unverified human investigation.
- Push delivery to physical devices (e.g. iOS Web Push) is a human on-device verification gate, not automated proof in CI/test suites.

## Code Shape

- Use kebab-case filenames, single quotes, and no semicolons.
- Prefer arrow-function React components and `I`-prefixed interfaces.
- Keep Herdr transport, socket client, and bridge in `server/`; keep browser API calls in `src/services/`.
- Image preview is image-only: `POST /api/media/image` reuses owner authentication and mandatory Origin checks before body, filesystem, or snapshot reads. It authorizes owner-requested local PNG/JPEG/WebP across the filesystem: absolute and `~/` paths require no pane context, while relative paths resolve authoritatively against the active pane's native `foreground_cwd` (fallback `cwd`) from `getHerdrSnapshot`. Preserve regular-file/descriptor identity (`lstat` before open with `O_NOFOLLOW | O_NONBLOCK`, dev/ino matching, canonical recheck), bounded body/file reads (12 MiB limit, 8192px/32MP dimensions), magic and dimension validation, no-store/nosniff, and generic errors. Terminal candidates are untrusted; never turn this into an unauthenticated file server, directory listing, or text reader, and never add SVG/video implicitly.
- T168 backend image context belongs to `server/image-upload.ts` (private bounded storage), `server/image-upload-service.ts` (owner/Origin, exact native Letta runtime and prompt readiness), and existing action/coordinator Send. POST `/api/media/uploads` accepts only a raw PNG/JPEG body <=8MiB plus allowlisted `X-Herdr-Image-Target` JSON; GET/DELETE `/api/media/uploads/<opaque-id>` authorize the same captured owner/runtime. Same-origin GET clients supply `X-Herdr-Image-Origin` because browsers do not normally emit Origin on GET; a real Origin always takes precedence, CORS remains closed. No filename/path/native private token is accepted or exposed. Native `letta_scope` + `letta_started_at` and exact terminal/available session are server-private fingerprint inputs; absent public agent_session does not manufacture one, missing native runtime evidence fails closed. Optional prompt-only `imageId` binds the operation fingerprint, composes an exact server-owned local-file ViewImage instruction, and applies the shared4096 UTF-8 byte budget using an opaque context-byte projection. Queue and terminal actions refuse imageId. One-shot possible dispatch consumes image authority even on unknown; removing submitted intent never deletes asynchronous agent-readable bytes. Opaque IDs invalidate on restart; generated0600 files under ignored `.agent-state/image-uploads` retain a single24h TTL with startup/upload pruning and bounded crash-orphan cleanup. HTTP bodies are capped before buffering (two concurrent, eight/minute,15s deadline); storage has32files/64MiB bounds. PNG/JPEG checks are bounded structural/dimension validation, not a full codec; WebP/APNG/MPF are excluded. Client cancellation after response loss must explicitly DELETE an eventual successful upload or rely on24h expiry. Browser image intent belongs to App's memory-only `use-composer-image` / `ComposerImageOwner`, browser image API/decode service and existing compact PromptComposer.
