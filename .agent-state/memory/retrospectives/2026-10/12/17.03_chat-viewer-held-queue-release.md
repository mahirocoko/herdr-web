## Honest feedback

1. The implementation took too many serial repair rounds. Independent review was useful because it disproved real safety claims, but parser-only retries should have ended earlier. The successful repair changed the authority owner rather than polishing the same regex again.
2. Browser fixtures and selectors were a substantial friction point. One QA lane lost its capability before discarding its own inert item; other passes had incomplete fixtures. These were execution failures, not product regressions, and their screenshots could not serve as clean acceptance evidence. The item remained unsent and expired; later live enqueue/discard completed correctly.
3. I underestimated compact control ownership. Adding Queue exposed a fixed-width trailing slot, and verbose informational labels created child overflow even when the document itself did not overflow. Direct raw inspection and measured child bounds were more useful than a generic responsive PASS. Future checks should inspect complete owned rows before claiming mobile correctness.

## Lessons and authority

Rejected parsing is not positive permission for a generic fallback; server records must own one-shot delivery beyond cache eviction; rendered child bounds matter more than document overflow alone. These decisions already have canonical fail-closed, lifecycle and UI guidance plus concrete repository regressions. Novelty does not justify another reference learning: **retrospective-only; no durable lesson promoted**.
