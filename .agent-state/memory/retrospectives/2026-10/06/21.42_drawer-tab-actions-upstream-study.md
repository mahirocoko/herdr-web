## Verification and Boundaries

- Writerรายงาน958pass/8skip; Mainตรวจเฉพาะงานที่เปลี่ยนและ build/typecheck หลาย checkpoint ไม่ได้อ้างว่ารัน full suiteใหม่หลังทุกการแก้
- Checkpointสุดท้ายของ header/menu:10testsผ่าน typecheck/buildผ่าน
- Independent browser QA ตรวจexact target ของ non-first Tab, last-tab guidance, Settings navigation, keyboard/Escape และ desktop/mobile geometry
- Unknown fixture: action requestเดียวถูก intercept และคืน504 gateคงอยู่เมื่อ refreshล้มเหลว เคลียร์เมื่ออ่าน snapshotสำเร็จ ไม่มี automatic retry ไม่มี live action mutation
- Focus regression: Menu→New/Close/Reviewไปอยู่ใน Drawer; Escapeจาก Menuปกติกลับ Trigger; console0errors/0warningsหลังแก้
- ภาพ mobileรอบแรกบัง headerด้วย sidebar จึงใช้เป็นหลักฐาน headerไม่ได้ ขอ captureใหม่และ Mainดูภาพจริงก่อนปิดงาน
- Upstream studyเป็น source evidenceเท่านั้น ไม่ใช่ runtime PASS/native capability/การรับรองให้ adopt
- ไม่มี formatter scriptหรือ formatter dependencyใน repo ไม่ติดตั้ง formatterเพิ่มเพื่อ closeout

## AI Diary

ผมเห็นชัดในรอบนี้ว่าการอ่านรายงานกับการอ่านภาพจริงให้คำตอบไม่เหมือนกัน รายงานแรกบอกว่าเมนูผ่าน แต่ปุ่ม `…` กลายเป็นพื้นขาวจาก browser default ถ้าหยุดตรงคำว่า PASS ก็จะส่งสิ่งที่มองเห็นว่าผิดให้ Mahiroลองอีกครั้ง ปัญหาไม่ได้อยู่ที่ไม่มี class ของ icon button แต่อยู่ที่ Triggerไม่ได้ใช้ Button recipeตัวจริง ผมต้องกลับไปดูเจ้าของ paint ไม่ใช่เพิ่ม CSSให้ดูคล้ายกัน

เรื่อง focusก็ทำให้ผมระวังคำว่า benignมากขึ้น ตอนแรก QAเรียก warningว่าเป็นผลจาก animationของ sheet แต่ข้อความจริงคือ focused elementอยู่ใน ancestorที่กำลัง aria-hidden นี่ไม่ใช่เรื่องตกแต่ง เมื่อเมนูส่งต่อไปเปิด Drawer การคืน focusของเมนูไปที่ headerควรถูกหยุด แต่เวลาใช้ Escapeปิดเมนูธรรมดายังต้องคืน focusเหมือนเดิม การแก้แค่จุดส่งต่อช่วยเก็บพฤติกรรมที่ดีเดิมไว้ ไม่ต้องเปลี่ยน focus systemทั้งชุด

ผมยังมีจังหวะทำงานที่ควรลดลง รายงานย่อยและคำว่าเหลือตรวจอีกจุดออกมาหลายครั้ง งานที่ควรจบเป็นช่วงสั้นเลยดูยืดออก ถึงแต่ละ follow-upจะมีเหตุผลจากหลักฐานใหม่ แต่การประกาศว่ารอบสุดท้ายก่อนรู้ว่าหลักฐานครบทำให้คำสรุปไม่น่าเชื่อถือเท่าที่ควร ครั้งต่อไปควรบอกสถานะเฉพาะเมื่อมีผลใหม่ที่เปลี่ยนข้อสรุปจริง ๆ

ตอน learn ผมเริ่มจากหาบันทึกเดิมก่อน เป็นสิ่งที่ถูกกับการมีหลาย Space เราไม่ควรคิดว่า current projectเป็นแหล่งความรู้ทั้งหมด แต่พอ Mahiroขอให้ pullใหม่ก็มี deltaถึง116ไฟล์ การใช้บันทึกเก่าอย่างเดียวจึงไม่พอ ต้องรักษา baselineเก่าแล้วสร้างเอกสารปัจจุบันแยกกัน ความต่างระหว่าง source HEADกับ releaseก็สำคัญ packageเขียน0.3.52ไม่ได้แปลว่าทุก commitบน mainอยู่ในเครื่องที่ติดตั้งแล้ว

หลังอ่านครบ ผมยังไม่ควรรีบเอาของ upstreamมาเปลี่ยน projectนี้เอง สิ่งที่เรียนรู้เป็นทางเลือกและข้อจำกัด ไม่ใช่คำสั่งให้ย้าย architectureหรือเพิ่ม feature การตัดสินใจรอบต่อไปต้องเริ่มจากสิ่งที่ Mahiroใช้จริง แล้วเทียบว่าของเขาช่วย outcomeไหนได้บ้าง เรามี lifecycle safetyและ UIที่ยอมรับแล้วเป็นฐาน ต้องนำจุดดีมาใช้โดยไม่ทำฐานนั้นหายไป

## Honest Feedback

1. **การปิดงานยืดจากหลักฐานที่ยังตรวจไม่ครบ** — Mainพบ defectหลังรายงาน PASSได้เป็นเรื่องดี แต่ข้อความเหลือรอบสุดท้ายซ้ำหลายครั้งสร้างความคาดหวังผิด งานนี้ควรจัด checklistที่ตรงกับ scopeตั้งแต่ต้น ทั้ง canonical paint, menu→modal focus, consoleหลัง interaction และภาพที่เห็น stateจริง ไม่ใช่เพิ่ม reviewerเพื่อความสบายใจ แต่ทำให้การรับหลักฐานครั้งแรกแม่นขึ้น

2. **QAที่มั่นใจยังรายงานผิดได้** — warningถูกเรียก benignโดยไม่มี exact signature และภาพ mobileไม่ได้แสดง headerที่อ้างว่าเก็บมา สองเรื่องนี้ยืนยันว่าความเป็น independentไม่ได้รับประกันคุณภาพ ต้องตรวจ pixelsและ runtime factsด้วย Mainปฏิเสธเฉพาะส่วนที่ผิด แล้วเก็บ evidenceที่ยังใช้ได้ไว้ ไม่ล้มการตรวจทั้งชุดหรือให้ rerunทุกอย่าง

3. **การศึกษา repoไม่ควรกลายเป็นการเริ่ม implementation** — รอบนี้ได้ source mapใหม่ครบ แต่ผลด้าน native declarations, release versionและ helper side effectsต้องมีขอบเขตชัด เราไม่ได้ทดสอบ nativeQuickCommands ไม่ได้เริ่ม Herdrtestsession และไม่ได้ installruntime การบันทึกความไม่รู้ตรงนี้ช่วยให้รอบวิเคราะห์ต่อไปเปรียบเทียบอย่างยุติธรรม ไม่ยกของเราให้เหนือกว่าเพราะคุ้นกับมัน หรือเชื่อ upstreamเพราะมี schemaกับtestsอยู่แล้ว

## Lessons Learned

- canonical recipe, runtime/state propagation, rendered correctness และ human acceptanceเป็นคนละหลักฐาน
- เริ่มจาก exact warningและภาพจริง ไม่ใช้คำว่า animation/benignแทน diagnosis
- เมนูที่เปิด modalต้องส่งต่อ focus ไม่ดึงกลับไปยัง hidden background
- ค้น learn registryข้าม workspaceก่อน และ pin sourceใหม่เมื่อมี pull
- Source HEAD, app releaseและ remote bundle versionเป็นคนละ owner
- รอบนี้ไม่สร้าง reference-learningใหม่ หลักการตรวจภาพ/console, owner boundariesและ no-auto-retryมีอยู่ใน guidanceแล้ว จึงไม่ผ่าน novelty gate บันทึกเป็น retrospective-only
