## AI diary

I began this work with the right architectural instinct: reuse an existing implementation rather than inventing another parser or a parallel state machine. I followed that instinct for Git diff rendering and several Chat behaviors, but I failed to apply it consistently to presentation. I treated the local primitive library as permission to simplify an already designed surface. That was not a necessary adaptation. It removed status chips, file glyphs, visual alignment, and color distinctions that the upstream author had deliberately provided. Functional tests and browser interactions then confirmed that my replacement worked without challenging whether it was the requested replacement at all.

Mahiro's correction was especially useful because the repaired surface immediately demonstrated the difference. I did not need another original visual concept. I needed to preserve the existing one while connecting it to our actual transport and security boundaries. The later source audit also prevented an opposite mistake: treating every local difference as a defect. The chosen navigation, single-path image reader, manual held queue, and submission history have their own owners. I need to preserve those decisions while recovering the source anatomy of features that were genuinely adopted. I also need to distinguish a blocked verification service from a failed product, and retain the evidence already earned instead of restarting the whole proof loop.

## Honest feedback

Three friction points stood out. First, I allowed adaptation to become redesign without naming that decision. This was avoidable: an anatomy map and a source-versus-local render early in the Changes implementation would have caught the monochrome list before the human had to ask. Second, several execution lanes ended with generic provider errors despite having completed their files. Resuming the same session recovered the results, but repeated status messages made the work feel more fragmented; reports and bounded artifacts mattered more than interpreting task transport success. Third, the verification plan was initially too broad for one browser pass. Later passes were justified by specific missing cases and reproduced defects, but I should have prioritized exact counterexamples and source fidelity earlier. The final security gate remains unresolved for a different reason, and I must not bury it beneath the large passing test count.

## Lessons learned

- Preserve source presentation as well as logic when the user selects an upstream feature; local primitives are integration tools, not a redesign license.
- Distinguish source ownership, propagation, rendered function, and human visual acceptance. No single test total covers all four.
- Recover exact human-owned exceptions before proposing restoration of older UI.
- Keep provider-blocked independent verification explicit and separate from implementation or authored regression results.

Learning promotion: retrospective-only; no new durable reference learning promoted. Existing agent guidance already communicates source fidelity and the four evidence gates; this incident reinforces application rather than adding another duplicate rule.
