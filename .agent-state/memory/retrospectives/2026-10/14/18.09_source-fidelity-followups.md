First, the implementation sequence was longer than it should have been because testing was distributed across several partial browser lanes. The final coverage was useful, but the harness should have been bounded and artifact-owned from the first run. Second, source fidelity needs actual reference rendering where possible. The FileViewer reference fixture repeatedly failed to mount due to dependency and module-loader boundaries. I stopped short of inventing a lookalike, but that means its strict A/B gate remains incomplete. Third, closeout must distinguish publication permission from technical assurance. A maintainer can ask for a release while a provider refuses a security recheck; neither event erases the other. A prerelease preserves useful delivery while retaining the honest limits and the stable version's status.

## Lessons learned

- Preserve reference-owned anatomy and explicit product-owned exceptions independently.
- Prefer one canonical state reader and narrow handoffs to duplicate stores or cards.
- Repeated focused tests must challenge actual user-visible outcomes, including keyboard focus during layout transitions.
- Label reference-fixture and provider failures as evidence gaps, not product failures or passing acceptance.
