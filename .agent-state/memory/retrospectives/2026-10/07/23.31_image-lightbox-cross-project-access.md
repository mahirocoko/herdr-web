## AI diary

I began this image proof with an intentionally narrow file boundary, but I let the initial implementation and my first checks stand in for the output that Mahiro actually reads. The simple fixture was useful for proving binary delivery and image dimensions. It was not enough to prove that an agent tool's aligned, wrapped filename was clickable. When Mahiro showed the real View Image output, I could reproduce the missing first-row link and truncated last-row target without another broad browser investigation. That was the better loop: exact evidence, one counterexample, then a small owner-level change.

I also learned something about the product shape. A functioning drawer was not the right place to inspect a picture. Mahiro's lightbox correction clarified the page job immediately, and I preserved the working transport while giving the presentation to a bounded Gemini writer. Separate rendered QA then measured the actual Dialog instead of accepting source class names. Later, all-project permission simplified a boundary I had initially made more restrictive than the user wanted. I kept authentication and real-image validation, but removed enrollment rather than adding a permission framework. Finally, reviewing the returned screenshot myself mattered: its filename promised an external-image preview, while its pixels showed a closed terminal. I retained valid network evidence and requested one targeted correction rather than restarting the whole verification chain.

## Honest feedback

1. The proof took too long for a small feature. Several useful corrections appeared only after broad readiness language, including native padded wrapping, agent-owned indentation and the drawer's poor fit for image viewing. I should start the next terminal affordance from a real agent output example and its actual user gesture, not from a clean synthetic line alone.
2. QA reports contained stronger claims than their evidence. Viewport dimensions did not necessarily prove native fitted-buffer geometry; an illustrative Fit calculation did not match measured dimensions; a screenshot filename did not prove the pictured state. I qualified those claims instead of repeating them, but should put the relevant raw-state postconditions into the packet earlier.
3. I originally treated application-root containment as a lasting product requirement. It was only an initial safety posture. Once Mahiro approved all-project images, preserving that posture would have created needless configuration friction. The right distinction was owner-authorized image access versus public/arbitrary-file access, with native cwd ownership kept explicit.

## Lessons learned

- Bind relative resource resolution to the authoritative producer context and freeze request identity at interaction time.
- Inspect the actual rendered artifact; preserve valid lower-layer evidence when one proof artifact is rejected.
- Recognized formatted-output continuation needs alignment and cell-coordinate ownership, not indiscriminate whitespace removal.
- Human-selected permission/presentation boundaries supersede provisional agent defaults, without weakening independent authentication and content guards.
